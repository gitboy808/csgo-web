# C4、装备掉落、自动拾取与开局预热

准备阶段为 3 秒。本页浏览器实测来自 2026-09-25，当前自动检查见 [VALIDATION.md](VALIDATION.md)。

## 原始资源与参考

资源继续使用本机 Steam 官方 depot：app 730 / depot 2347770 / manifest `5009084625236407721`。

- C4：`weapons/models/c4/weapon_c4.vmdl_c`；拆弹工具：`weapons/models/defuser/defuser.vmdl_c`。
- 动作：`animation/anims/viewmodel/equipment/c4/` 中的 idle、draw、plant、lookat01。原始安装片段长 4 秒，在本游戏既定的 3.2 秒安装规则下同步播放。
- 音效：35 段 C4 专用按键、取出、安装、倒计时、拆除和爆炸采样。通用 Draw.Gear 复用投掷物音库中的 5 段相同采样，避免重复加载与解码；C4 专用清单在 public/assets/source2/c4/audio.json。
- 模型保留原始几何、骨骼和 PBR 材质，纹理上限 2048，使用无损 WebP 与 Meshopt。运行资源约 12.1 MiB。原引擎的 Panorama LCD 由浏览器画布接管，修复了导出面板的背面和水平镜像问题；按安装进度显示密码。
- 掉落规则参照 [CS2 竞技模式原始配置](https://raw.githubusercontent.com/SteamDatabase/GameTracking-CS2/master/game/csgo/cfg/gamemode_competitive.cfg)中的主武器、投掷物和拆弹工具死亡掉落选项。
- 预热依据当前安装的 Three.js r186 源码及 [WebGLRenderer 文档](https://threejs.org/docs/#WebGLRenderer)。普通离屏目标使用的输出颜色/色调处理变体与屏幕不同；因此在不透明加载界面后，用实际屏幕输出路径预热，并暂时缩小 viewport。
- 掉落物使用 [Rapier 休眠机制](https://rapier.rs/docs/user_guides/javascript/rigid_body_sleeping/)，并启用连续碰撞检测。

重建：

```sh
pnpm exec tsx scripts/prepare-source2-c4.ts
pnpm check:assets
```

需要已有的本机 VPK、VRF helper 和武器声音定义。补齐的原始分包列表在 `local-assets/c4/depot-files.txt` 与 `audio-depot-files.txt`；原始包不进入网页产物。

## 游戏行为

- C4 使用原始世界模型和带手臂的第一人称模型，支持取出、检视、安装动作。按 5 选择，包点内长按左键或 E 安装，G 丢下，F 检视。安装完成或丢下后重新取出枪械。
- C4 安装后按地面法线和安装者朝向摆放；掉落的 C4 具有实体运动。T 可以接近自动拾取，已安装的炸弹不能被拾取。
- 死亡掉落主武器，缺少主武器时掉落手枪；修复持刀死亡不掉枪的问题。投掷物按当前/可用类型掉落，CT 的拆弹工具也会掉落。
- 武器、投掷物和拆弹工具带有抛出速度、转动、重力、碰撞和休眠。落地状态随地形与初始运动变化。保留枪内弹药与备弹，拾取不会补满。
- 自动拾取填充空武器槽，不覆盖已持有的同槽武器，不强制切走玩家正在使用的武器。按 E 明确替换附近武器。机器人会使用拾取到的更高优先级武器。
- 投掷物遵守携带上限；拆弹工具只供 CT 拾取。检查距离、高度和视线，不能隔墙或跨楼层拾取。自己刚扔出的装备有 0.8 秒拾取保护。

这里使用原始资源，但碰撞体、弹跳阻尼、LCD 和拾取触达范围是浏览器重建。Rapier 的落地轨迹不等同于 Valve 的物理引擎，未宣称逐帧一致。

## 行为回归与历史实测

- 初始回归复现了“无 E 不拾取”和“持刀死亡不掉主武器”，修复后通过。
- 物理检查：抛落、薄墙连续碰撞、落地休眠、拾取销毁物理体、休眠后不再写变换。
- 拾取检查：空槽自动拾取、同槽保留、E 替换、弹药保留、隔墙禁止、自抛保护。
- 原始 CT/T 骨骼测试确认：死亡动作结束后的 120 次更新中，动画混合器调用从 120 次变为 0，最终姿态保持不变，复活后正常恢复。
- 浏览器：原始 C4 持握、安装、地面朝向显示正常；自动拾取 AK 保留 7 发弹匣 / 23 发备弹，当前手持匕首不变。安装中断、安装和拆除回归通过。
- 最终预热测得约 5.6 秒，连同屏幕、线性世界和合成变体提前完成 121 个着色器程序；第一次依次切换七种武器，程序数量保持 **121 → 121**。这是当前机器与缓存状态下的测量，不是固定加载耗时。

当前测试、构建与实战性能汇总见 [VALIDATION.md](VALIDATION.md)。

最终实战采样：九机器人起始，1,800 帧，帧间隔中位数 / p95 为 16.7 / 24.8ms；渲染帧主线程工作中位数 / p95 为 3.6 / 5.9ms。存活人数与视角随对局变化，不是与旧版本完全相同场景的严格对照，也不代表全程锁定 60 FPS。
