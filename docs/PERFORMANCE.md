# 渲染性能策略

开局前进行视模、热点机位、静态阴影和屏幕/线性输出变体预热；地面枪械使用共享静态网格，落地休眠，死亡动作结束后停止重复求值。实测与取舍见 [LOCAL_C4_LOOT.md](LOCAL_C4_LOOT.md)，当前校验入口见 [VALIDATION.md](VALIDATION.md)。

默认保持高画质与原始模型、贴图，新增 60 / 90 / 120 FPS 上限，默认 60。设置里可选动态分辨率，默认关闭。

## 已采用的方案

1. **按需渲染**：暂停、购买和设置界面中的静止战场停止动画循环；后台标签页停止 3D 绘制。菜单背景为 30 FPS。地图浏览在拖动、缩放、阻尼动画结束后停绘，交互和窗口调整会唤醒。音乐调度独立运行，不依赖连续重画地图。
2. **帧率预算**：只限制绘制提交，保留原来的固定 60 Hz 比赛模拟和输入缓存。高刷新屏默认不再无上限提交约 120 帧。
3. **静态阴影缓存**：保留 4096 阴影分辨率。先保存建筑深度，后续复用该深度，再绘制移动人物和物件，最终继续使用原生硬件 PCF。没有删掉建筑对人物的遮挡，也没有将两张已经过滤的阴影简单相乘。画质变化时重新生成缓存。
4. **保守可见性与距离分级**：角色和世界枪械使用涵盖动作的包围体。只有角色和可能投向可见区域的阴影都在画面外，才跳过其绘制和骨骼更新。45 米外人物动作按 30 Hz 更新，近处人物与第一人称动作保持当前渲染频率；AI、碰撞、射击逻辑不参与此降频。
5. **可选动态分辨率**：持续达不到帧率预算时，场景以 5% 步长降至最低 85%，稳定后缓慢恢复。一次加载卡顿不会触发降级。只缩放世界场景，第一人称武器和 HTML 界面保持完整分辨率。100% 且无需烟雾合成时直接绘制；需要合成体积烟雾时，使用世界渲染目标提供深度与颜色。
6. 已移除旧生成地图使用的 SSAO / EffectComposer 路径；调节音量不会重建阴影贴图。

## 音频与音乐

命中音效共享一次解码结果，最多 24 路同时发声；音乐只流式播放当前曲目，最多一条当前流与一条短暂淡出流。新增九套音乐不会全部预载。音乐盒从主页打开时也停止背景 3D 绘制，静止试听两秒新增绘制为 0。原枪械 / 投掷物音效不再保留重复压缩字节。体积、提交压力与释放记录见 [LOCAL_HIT_AUDIO_MUSIC.md](LOCAL_HIT_AUDIO_MUSIC.md)。

## 行为回归与历史测量（2026-09-25）

- `tests/render-energy.test.ts` 直接驱动实际 `Game.frame`：旧版暂停 1 秒仍提交 121 次绘制；修复后只有按需的初始帧。后台无绘制，限帧后模拟仍为 60 Hz。
- 浏览器暂停抽样：连续 3 秒新增绘制 **0 次**，动画循环停止。
- 九个固定机位比较完整阴影与缓存阴影，384 × 216 离屏像素逐通道比较全部通过，最大差异 **0**。
- 例如 A 包点：单次绘制由 **1204 次调用 / 5,729,603 三角形** 降至 **332 / 1,238,149**；B 包点由 **1034 / 4,988,905** 降至 **162 / 497,451**。这是同一画面中包含阴影的提交数量，不是显卡功耗降低百分比。
- 动态分辨率检查：画布 2176 × 1224、世界目标 1850 × 1040（85%），武器仍在完整画布上绘制，未出现 WebGL 错误。
- 浏览器输入缓存、命中/石墙/木材、炸弹取消/安装/拆除、三连发、换弹扣弹、后坐力回正均通过。

没有采集芯片温度或 GPU 功耗，因此不把以上工作量下降换算成降温幅度。旧版专用 QA/压测面板已删除。需要重新比较性能时，应固定场景并使用只读性能诊断或浏览器性能工具；历史采样不作为当前版本帧率保证。

## 官方资料与适用范围

- [Apple：改善游戏图形性能与设置](https://developer.apple.com/documentation/metal/improving-your-games-graphics-performance-and-settings)：为 CPU / GPU 分别设定帧时预算，并通过帧率、分辨率和细节等级适应便携设备能耗。
- [Three.js：按需渲染](https://threejs.org/manual/pages/rendering-on-demand.html)：静止内容不用持续重画，输入和尺寸变化触发新帧。
- [Three.js：阴影](https://threejs.org/manual/pages/shadows.html)：投影物体会产生额外渲染，静态光照适合提前计算或复用。
- [MDN：WebGL 最佳实践](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)：注意高 DPI 像素数量、批处理、mipmap 和 GPU 资源成本。
- [Apple：游戏模式](https://support.apple.com/105118)：主要提高 CPU/GPU 调度优先级，并非降温功能；本项目未依赖它。
- [Three.js：KTX2Loader](https://threejs.org/docs/pages/KTX2Loader.html)：GPU 纹理压缩可作为后续资源优化，但当前保留原始无损贴图。MetalFX 属于原生 Metal 方案，不能直接作为当前 WebGL 页面的一项开关。

## 投掷物增量

投掷物继续使用本页的按需绘制和阴影缓存。体积烟雾复用世界深度并在独立低分辨率层合成；火焰实例化、爆炸/粒子/模型池化，暂停不会为特效恢复持续绘制。九角色 + 六烟 + 两火的对照实测见 [LOCAL_GRENADES.md](LOCAL_GRENADES.md)。
